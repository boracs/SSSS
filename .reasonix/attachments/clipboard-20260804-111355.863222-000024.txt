BACKEND
════════════════════════════════════

1) DTO readonly
app/DTOs/SurfConditions/ZurriolaWeatherForecastDto.php
Campos mínimos (ajusta nombres al estilo del dominio):
- fetchedAt: string ISO
- hourly: list<ZurriolaWeatherHourDto>  (o array de readonly DTOs anidados)
- daily: list<ZurriolaWeatherDayDto>
Cada hour: time, temperatureC, precipProbabilityPct, cloudCoverPct,
  windSpeedKmh, windDirectionDeg, windGustsKmh, uvIndex, weatherCode
Cada day: date, tempMaxC, tempMinC, precipProbabilityMaxPct,
  sunrise, sunset, weatherCode
Método toArray() para JSON limpio (listas de objetos, NO columnas Open-Meteo crudas).

2) Client
app/Services/SurfConditions/OpenMeteoWeatherClient.php (final)
- Replica estilo OpenMeteoMarineClient (Http::timeout(8|10), Log::warning, excepción
  de dominio si falla — reutiliza SurfConditionsUnavailableException si encaja).
- Endpoint: https://api.open-meteo.com/v1/forecast
- lat/lon/timezone SOLO desde config('services.zurriola_surf')
- Params:
  hourly: temperature_2m,precipitation_probability,cloud_cover,
          wind_speed_10m,wind_direction_10m,wind_gusts_10m,uv_index,weather_code
          (visibility opcional; omítela si complica unidades)
  daily: temperature_2m_max,temperature_2m_min,precipitation_probability_max,
         sunrise,sunset,weather_code
  forecast_days: 7
  timezone: config timezone
- Método: fetchForecast(): ZurriolaWeatherForecastDto
  Normaliza el payload columnar de Open-Meteo → listas de horas/días en el DTO.
  Filtra hourly a desde la hora actual (timezone Madrid) hacia adelante
  (máx. 48 entradas; el front puede mostrar 24 por defecto).

3) Service (orquestación + cache)
app/Services/SurfConditions/ZurriolaWeatherForecastService.php
- publicPayload(): array
- Cache::remember('zurriola.weather.forecast.v1', now()->addMinutes(45), fn () => ...)
- Si config weather deshabilitado → array vacío o flag enabled:false
- try/catch: si Open-Meteo cae, no 500 HTML; respuesta JSON controlada
  { ok: false, message: '...' } con 503 o 200+ok:false (elige uno y documenta).

4) Controller fino
app/Http/Controllers/SurfConditions/ZurriolaWeatherController.php
  (o SurfBrief/ si prefieres colocalizar con webcams — una sola carpeta coherente)
- __invoke o show(): return response()->json($service->publicPayload())
- Cero lógica de parseo aquí.

5) Ruta
En routes/web.php junto a webcams (Ziggy-friendly), nombre sugerido:
  Route::get('/servicios/webcams/tiempo', ...)->name('servicios.webcams.weather');
Pública, GET, sin auth.
No hace falta api.php salvo que el proyecto ya exponga este tipo ahí.

6) Config
En config/services.php dentro de zurriola_surf:
  'weather_detail_enabled' => env('ZURRIOLA_WEATHER_DETAIL_ENABLED', true),
No hardcodees coordenadas nuevas.
